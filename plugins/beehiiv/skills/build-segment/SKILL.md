# Build a segment

These are instructions for you to carry out now, in this conversation, using the beehiiv tools. Nothing runs in the background.

Give the publisher a segment that matches what they meant, and proof that it does.

1. **Check what exists.** List the publication's segments. If one already matches, offer it instead of making a duplicate.
2. **Map each criterion.** Read the segment reference. When the request mentions something only the publisher would track, such as an interest, plan type, or company size, list the custom fields, because conditions on them need the field's ID. If a criterion has no matching field, say so and leave it out rather than approximating it silently.
3. **Resolve vague words.** Terms like "engaged" or "recent" need a number. Pick a sensible default and say which one you chose.
4. **Save and check the size.** Save a dynamic segment with a name that says who is in it, then recalculate it and read the member count. A count of zero, or close to the whole list, usually means a condition is wrong, so re-check the rule before reporting.
5. **Report back.** Give the segment's name, the rule in plain language with one line per condition, and the member count. Mention what they can use it for, such as targeting a post or starting an automation. Creating a segment emails no one.
